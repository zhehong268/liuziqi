# 平台核对与六子棋提交

核对日期：2026-11-14（北京时间）。实际查看了首页、六子棋赛道页、客户端说明，并下载阅读开发模板的 `protocol/arena-v1.md`、`python/bot.py`、`README.md`。

## 可选棋种

平台首页只有以下三条赛道，没有五子棋：

| 棋种 | 平台标识 | 棋盘 |
| --- | --- | --- |
| 九路围棋 | `go9` | 9×9 |
| 六子棋 | `connect6` | 19×19 |
| 点格棋 | `dotsboxes` | 6×6 点、25 个格 |

本 Demo 选六子棋：不需要先实现围棋的提子、劫和数子，也方便用二维棋盘解释策略及 Agent 复盘。

## 已核对的六子棋规则

- 黑先，首回合 1 子，其余回合各 2 子。
- 每次 AI 请求只对应一颗子，不是一次返回两个坐标。
- 任意方向 6 子或以上相连，立即获胜；下满和棋。
- 无 PASS、无禁手、无认输动作。
- `row` 向下、`col` 向右，坐标从 0 开始。
- 棋盘 `0` 为空、`1` 黑、`2` 白。按 `observation.current_player` 判断行动方。
- 每次决策硬超时 10,000 ms；超时、非法落子、协议错误会判负。

页面规则版本为 `connect6-baseline-v1`，公共协议版本为 `arena.v1`。

## 协议信封

请求示意（`board` 必须是真实 19×19 数组，下面省略了观察内容）：

```json
{"protocol":"arena.v1","request_id":"t1","type":"move_request","game":"connect6","player":1,"observation":{}}
```

响应示意：

```json
{"protocol":"arena.v1","request_id":"t1","type":"move_response","action":{"kind":"PLACE","row":9,"col":9}}
```

一局只启动一个常驻进程，逐行读 stdin，逐行写 stdout 并立即 flush。响应不得超过 4 KB。stdout 不能混入调试日志；日志写 stderr。Python 只用标准库，评测时不联网，不创建额外线程/子进程。

## 本项目如何提交

1. 在[客户端页面](http://139.196.148.174/client)下载学生客户端。
2. 按页面要求准备 Windows 10/11 64 位和启用 Linux 容器的 Docker Desktop。
3. 登录自己的平台账号，选择六子棋、Python 3。
4. 上传项目根目录的 `bot.py`，可直接传单个 `.py` 文件。
5. 填写真实的版本备注，例如“初版：优先成六、封堵、连线评分”。
6. 开始本机评测，客户端完成两局，各先手一次，服务器校验后更新榜单。
7. 修改代码后重新上传新版本；平台评测使用已上传的固定版本。

上传的是策略源码。Web 项目的 Flask、数据库、静态页面和可选模型接口不随 `bot.py` 一起运行。GitHub 上传的是完整 Web 项目，平台上传的是下棋程序，两种交付都要保留版本记录。

## 本地自测

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试会启动一个 `bot.py` 进程，连续发送两行请求，检查回显 ID、响应格式、坐标、无额外 stdout 和响应大小，同时检查规则与 AI 完整对弈。这里只证明本地协议可用，尚未在登录后的客户端完成正式评测，不宣称获得平台认证。

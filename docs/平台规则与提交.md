# 平台提交

入口：[六子棋赛道](http://139.196.148.174/connect6) · [学生客户端](http://139.196.148.174/client) · [开发模板](http://139.196.148.174/sdk/student-sdk.zip)

以下按 2026-11-14 的赛道页面和开发模板整理。

## 规则

19×19，黑先。黑方首回合一颗，其余回合各两颗，六连或以上获胜，下满和棋。没有 PASS、禁手和认输动作。

一次请求只返回一颗。`board[row][col]` 中 0 为空、1 为黑、2 为白；行向下、列向右，从 0 开始。行动方读取 `observation.current_player`。

规则版本为 `connect6-baseline-v1`，协议为 `arena.v1`。单次决策上限 10,000 ms，超时、非法落子和协议错误都会判负。

## 上传

客户端需要 Windows 10/11 64 位和启用 Linux 容器的 Docker Desktop。

1. 登录客户端，选择六子棋、Python 3。
2. 上传项目根目录的 `bot.py`。
3. 填写版本备注，开始评测。
4. 客户端执行两局，各先手一次，再把结果交给服务器校验。

修改策略后要重新上传，评测使用的是已经上传的版本。`bot.py` 仅用标准库，不需要提交 Web 项目的其他文件。

## 标准输入输出

一局启动一个常驻进程，每读到一行请求，输出一行响应并 flush。stdout 只能写协议 JSON，调试日志写 stderr。响应上限 4 KB，评测代码不能联网或创建额外线程、子进程。

请求示意，省略了 `observation` 中的 19×19 棋盘等内容：

```json
{"protocol":"arena.v1","request_id":"t1","type":"move_request","game":"connect6","player":1,"observation":{}}
```

响应：

```json
{"protocol":"arena.v1","request_id":"t1","type":"move_response","action":{"kind":"PLACE","row":9,"col":9}}
```

`request_id` 原样回显。完整字段见开发模板中的 `protocol/arena-v1.md`，本项目的适配代码在 `bot.py` 的 `main()` 和 `decide()`。

## 自测

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

协议测试会向同一个 `bot.py` 进程连续发两条请求，检查响应格式、ID、坐标和大小。另有 AI 自我对弈测试。

目前只做了本地测试，还没跑客户端正式评测。项目导出的 TXT/JSON 尚未适配平台回放器。开发模板的评分摘要与赛道网页有差异，正式计分按平台结果。

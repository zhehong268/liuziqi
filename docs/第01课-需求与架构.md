# 第 01 课：把需求拆成可以运行的系统

> 这是早期阶段的教学顺序。当前可运行版本已包含本地 Agent、回放和导出，实际功能见根目录 README。

## 1. 先固定最小需求

第一版只做四件事：创建棋局、落子、保存棋谱、和基线 AI 对战。大模型分析、登录、排行榜和部署都放到后续迭代。这样每一步都能运行和提交，Git 历史才有意义。

## 2. 浏览器和服务器的分工

浏览器负责显示棋盘、监听点击、发送 JSON 请求。Flask 服务器负责校验规则、决定合法性、写入 SQLite。浏览器不能直接决定“这一步赢了”，否则用户可以修改前端代码作弊。

```text
浏览器 app.js
    │  POST /api/games/:id/moves {row, col}
    ▼
Flask app.py ── 读取/写入 ── SQLite data/connect6.db
    │
    └── 返回最新棋局 JSON
```

## 3. 数据库为什么存“每一步”

只保存当前棋盘，无法回放，也很难让 Agent 找到关键失误。`moves` 表保存 `move_no、player、row、col`，棋盘可以由这些记录重新计算。这个设计同时满足对局存储、棋谱导出和后续 AI 分析。

## 4. 今天的练习

启动项目后打开浏览器开发者工具的 Network 面板，下一步棋，找到 `POST /api/games/<id>/moves`，观察 Request JSON 和 Response JSON。再刷新页面，访问 `GET /api/games/<id>`，确认棋局是从数据库恢复的。

## 5. 课堂检查

- 能说出一次落子的请求方法、URL、请求体和响应体。
- 能解释为什么数据库里需要 `game_id` 和 `move_no`。
- 能指出 AI Key 应该放在哪一层，以及为什么不能放进 `static/app.js`。

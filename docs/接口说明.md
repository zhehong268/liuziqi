# 接口说明

服务默认监听 `http://127.0.0.1:5000`。除源码上传使用 multipart/form-data 外，请求和响应使用 JSON。

## 路由

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 服务状态和模型配置状态 |
| GET | `/api/games` | 最近 50 局 |
| POST | `/api/games` | 创建棋局 |
| GET | `/api/games/<id>` | 读取棋盘、棋谱和对应复盘 |
| POST | `/api/games/<id>/moves` | 玩家按本局执子落一颗 |
| POST | `/api/games/<id>/ai-turn` | AI 下完本回合剩余棋子 |
| POST | `/api/games/<id>/analysis` | 读取或生成复盘 |
| GET | `/api/games/<id>/export?format=txt` | 下载文本棋谱 |
| GET | `/api/games/<id>/export?format=json` | 下载 JSON 棋谱 |
| GET | `/api/arena` | 对战环境、官方版本和资源限制 |
| GET | `/api/arena/example` | 下载单文件 Python AI 示例 |
| GET | `/api/submissions` | 最近 50 个上传版本 |
| POST | `/api/submissions` | 上传代码；multipart/form-data，字段为 `name`、`file` |
| POST | `/api/arena/matches` | 发起挑战，返回 202 和棋局 |
| POST | `/api/arena/matches/<id>/cancel` | 停止挑战，保留已下棋谱 |

挑战请求体：

```json
{"submissionId":"上传返回的 id","challengerColor":"black"}
```

`challengerColor` 可为 `black` 或 `white`。使用 `GET /api/games/<id>` 轮询棋局进度。挑战局不能通过手动落子或 `/ai-turn` 接口修改，返回 409。对战过程中不能调用分析接口，终局自动生成复盘。

## 新建与落子

创建棋局的请求体：

```json
{"opponent": "local", "humanColor": "white"}
```

`opponent` 默认为 `local`。配置外部模型后也可用 `model`。`humanColor` 可为 `black`（默认，玩家先手）或 `white`（玩家后手）。创建成功返回 201 和完整棋局，其中 `id` 用于后续请求。

新棋局还没有落子。玩家执白时，前端紧接着请求 `/ai-turn`，由黑方 AI 下首颗子；恢复到 AI 回合时也通过这个接口继续。后端始终按棋局保存的颜色校验回合。

落子的请求体：

```json
{"row": 9, "col": 9}
```

行、列从 0 开始，必须是整数。玩家颜色由创建棋局时的 `humanColor` 决定，回合和占用情况由后端检查。落子成功返回更新后的棋局。

## 棋局数据

主要字段有 `id`、`status`、`winner`、`currentPlayer`、`remainingStones`、`board`、`moves` 和 `analysis`。

人机棋局还包括 `humanColor` 和 `aiColor`；历史列表包含 `humanColor`。旧棋局自动补为玩家执黑。挑战棋局的这两个字段为 `null`，挑战方颜色仍由 `arena.challengerColor` 表示。TXT / JSON 棋谱也记录执子。

`status` 为 `active`、`finished`、`draw` 或 `aborted`；棋盘空位为 `null`，黑白棋为 `"black"` / `"white"`。结束后 `currentPlayer` 为 `null`，`remainingStones` 为 0。

挑战棋局的 `opponent` 为 `arena`，`arena` 对象包含双方名称、挑战方颜色、官方哈希、运行状态、判定原因、当前思考方和开始时间。`arena.state` 为 `queued`、`preparing`、`running`、`finished` 或 `aborted`。每颗落子的 `elapsedMs` 为服务器记录的思考耗时；旧棋谱和人机练习为 `null`。

`analysis` 只返回与当前落子数量对应的复盘，没有时为 `null`。`/analysis` 会复用已存结果；继续下棋后可生成新结果。

## 导出与错误

TXT 使用从 1 开始的行列坐标，JSON 使用从 0 开始的坐标。两种格式都是下载响应。

非法输入返回 400，棋局不存在返回 404，状态冲突返回 409，请求体过大返回 413，Docker 不可用返回 503。错误响应的 `error` 字段包含原因。文件上限为 512 KB，整个上传请求上限为 600 KB。

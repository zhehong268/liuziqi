# 接口说明

服务默认监听 `http://127.0.0.1:5000`，请求和响应使用 JSON。

## 路由

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 服务状态和模型配置状态 |
| GET | `/api/games` | 最近 50 局 |
| POST | `/api/games` | 创建棋局 |
| GET | `/api/games/<id>` | 读取棋盘、棋谱和对应复盘 |
| POST | `/api/games/<id>/moves` | 黑方落一颗 |
| POST | `/api/games/<id>/ai-turn` | AI 下完本回合剩余棋子 |
| POST | `/api/games/<id>/analysis` | 读取或生成复盘 |
| GET | `/api/games/<id>/export?format=txt` | 下载文本棋谱 |
| GET | `/api/games/<id>/export?format=json` | 下载 JSON 棋谱 |

## 新建与落子

创建棋局的请求体：

```json
{"opponent": "local"}
```

`opponent` 默认为 `local`。配置外部模型后也可用 `model`。创建成功返回 201 和完整棋局，其中 `id` 用于后续请求。

落子的请求体：

```json
{"row": 9, "col": 9}
```

行、列从 0 开始，必须是整数。用户执黑，回合和占用情况由后端检查。落子成功返回更新后的棋局。

## 棋局数据

主要字段有 `id`、`status`、`winner`、`currentPlayer`、`remainingStones`、`board`、`moves` 和 `analysis`。

`status` 为 `active`、`finished` 或 `draw`；棋盘空位为 `null`，黑白棋为 `"black"` / `"white"`。结束后 `currentPlayer` 为 `null`，`remainingStones` 为 0。

`analysis` 只返回与当前落子数量对应的复盘，没有时为 `null`。`/analysis` 会复用已存结果；继续下棋后可生成新结果。

## 导出与错误

TXT 使用从 1 开始的行列坐标，JSON 使用从 0 开始的坐标。两种格式都是下载响应。

非法输入返回 400，棋局不存在返回 404。AI 思考期间棋局被其他请求修改时返回 409。错误响应的 `error` 字段包含原因。

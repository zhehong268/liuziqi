# 第 02 课：把棋谱交给 Agent

## 1. 先区分两种 AI

对战 AI 是提交给裁判的代码型算法。它只接收棋盘状态，返回一个合法落点，不需要 API Key，不应该访问外网。项目中的 `choose_ai_move()` 就是这种基线算法。

Agent 分析是另一个功能。它读取已经保存的棋谱，告诉用户哪里可以改进。项目默认使用 `local_analysis()`，所以没有 API Key 也能运行；配置 Key 后才会调用大模型生成更自然的文字说明。

## 2. Agent 放在哪一层

前端只请求 `POST /api/games/<id>/analysis`。Flask 从 SQLite 读取棋谱，整理成 Prompt，再由 `agent.py` 调用模型。这样 API Key 只存在服务端环境变量中，浏览器永远看不到它。

## 3. 最小调用结构

项目使用 OpenAI Python SDK 的 Responses API：

```python
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
response = client.responses.create(
    model=os.getenv("OPENAI_MODEL") or "gpt-5.5",
    instructions="你是一名耐心、具体的六子棋教练。",
    input=prompt,
)
text = response.output_text
```

Responses API 是新项目推荐的文本生成接口，`response.output_text` 可以读取模型文本结果。模型名用环境变量控制，换模型不需要修改业务代码。

## 4. 为什么要求 JSON

如果 Agent 返回一大段自然语言，前端很难稳定显示。这里要求 `summary、keyMistakes、strengths、nextPractice` 四个字段，再用 `json.loads` 做一次解析。真正参赛或上线时，还要继续加 JSON Schema 校验、长度限制、超时和重试。

## 5. 练习

1. 不配置任何 Key，启动服务，下一局棋后点击“用 Agent 分析本局”，观察本地规则 Agent 的结果。
2. 如果有可用模型，再复制 `.env.example` 为 `.env`，填写 API Key 和模型名，对比两种分析结果。
3. 故意下一步明显的堵漏棋，观察 Agent 是否能指出具体手数。
4. 把 `agent.py` 的本地分析规则或教练提示词改成你自己的版本，提交一次 Git。

不要把 `.env` 提交到 GitHub。API Key 泄露后应立即撤销并更换。

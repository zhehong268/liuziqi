# 第 02 课：接入自己的代码 AI 与复盘 Agent

## 1. 先跑通不需要 Key 的版本

本任务提交的是**自己编写的程序**。`bot.py` 通过 stdin 接收平台棋盘，再通过 stdout 输出一个落点。它没有网络请求，不需要 API Key，只有 Python 标准库依赖。

Web 端也直接使用它：

```text
浏览器点击
    ↓ POST /api/games/<id>/moves
Flask 校验并保存黑方落子
    ↓ 黑方回合结束
POST /api/games/<id>/ai-turn
    ↓ agent.choose_agent_move(opponent="local")
bot.choose_ai_move(board, "white")
    ↓ 返回 (row, col)，再校验并保存
浏览器显示 AI 的棋子
```

因此“接入自己的 AI”的第一步是修改 Python 策略函数，而不是申请 Key。

本版策略按顺序执行：

1. 枚举空位，检查自己下一颗能否成六，能就下。
2. 检查对手下一颗能否成六，有就封堵。
3. 给其他位置打分：己方延伸、对手延伸、邻居数量、靠近中心。
4. 返回得分最高的合法位置。

`winning_cells()` 临时试落后会恢复棋盘，不把试算当成真实落子。数据库只记录 `place_one()` 确认的动作。

这不是官方 baseline 的源码，是本项目自己的教学算法。棋力只要求能下棋，下一轮可以优化双子组合、活四/活五等判断。

## 3. 平台如何调用同一份代码

`bot.py` 的 `main()` 是常驻循环：每读到一行 JSON，就执行 `decide()` 并输出恰好一行 JSON。

`decide()` 负责协议适配：检查游戏类型，读取 `observation.board`，把 0/1/2 转为 None/black/white，再调用同一个 `choose_ai_move()`。`request_id` 原样回显。调试信息只能写 stderr。

平台一次决策是一颗子，所以不能输出两个落点。回合的第二颗由裁判再次发起请求。不能按黑白交替逐颗推断行动方，应读取 `observation.current_player`。

## 4. 本地复盘 Agent 做了什么

这是一个**固定流程 Agent**，任务是评估黑方（用户）的棋谱。

| 阶段 | 本项目调用的代码 | 结果 |
| --- | --- | --- |
| 读取 | Flask 从 SQLite 取 `moves` | 获得真实棋谱 |
| 观察 | `local_analysis()` 逐颗重建棋盘 | 恢复每一步局面 |
| 检查 | `winning_cells(board, "white")` | 查找白方可直接成六的落点 |
| 评估 | 仅在黑方完整回合结束后检查漏防 | 避免把两颗子之间的中间状态当成最终失误 |
| 输出 | 生成 summary、keyMistakes、strengths、nextPractice、trace | 给出具体手数和建议 |
| 记忆 | 写入 `analyses`，关联棋局及落子数 | 刷新后保留，可随棋谱版本查看 |

Agent 使用棋局工具和保存的状态完成任务；它不是多轮自主规划的复杂 Agent，也不是大模型训练系统。页面“查看 Agent 执行过程”展示固定步骤，便于解释作业。

示例：如果黑方下完两颗后，白方可在第 1 行第 6 列直接连六，复盘会指出本回合结束手数和该位置。它不证明所有失误：未发现直接漏防不代表每步都正确。

## 5. 先做一次自己的迭代

1. 运行项目，选择“我的规则 AI · 离线”，玩几回合。
2. 点击“分析当前棋局”，查看具体建议和执行过程。
3. 打开 `bot.py`，找到评分公式，例如 `own * own * 5 + enemy * enemy * 4 + neighbors`。
4. 自己尝试调整防守权重，重启后端，对比同一开局的落点。改变权重是实验，不保证变强。
5. 记录观察，运行测试，提交并推送：

```powershell

git add bot.py docs/迭代日志.md
git commit -m "feat: experiment with defensive move weights"
git push
```

把测试局面的特点、改动和实际结果写进 `docs/迭代日志.md`。有结果再写结论，不预填“提升棋力”。

## 6. 可选扩展：让外部模型参与 Web 对战和复盘

这一节不是平台提交要求，也不是运行初版的前提。只有你希望把已保存棋谱交给外部模型解释时才配置。平台提交仍然只使用 `bot.py`，没有这部分依赖。

```powershell
Copy-Item .env.example .env
notepad .env
```

填写服务商给你的 `OPENAI_API_KEY`、可调用的 `OPENAI_MODEL`。官方 OpenAI 接口可保持 `OPENAI_BASE_URL` 为空，并使用 `AI_API_STYLE=responses`。仅支持 Chat Completions 的兼容服务需要设置它提供的基础地址和 `AI_API_STYLE=chat`，同时支持 JSON mode。模型名和兼容性以该供应商文档及你的账号权限为准。

配置后重启 `app.py`、刷新页面。选择“大模型 AI · 已配置”并新建棋局，模型才会参与落子。已填写 Key 时，尚未缓存的复盘也会调用模型。一次 AI 回合最多调用两次（逐颗落子）；终局复盘另需一次，可能产生服务费用。清空 Key 并重启即可回到完全离线版本。配置后用新棋局验证，旧棋谱会复用已存结果。

后端的核心调用如下：

```python
with OpenAI(api_key=key, base_url=base_url, timeout=20, max_retries=0) as client:
    response = client.responses.create(
        model=model,
        store=False,
        instructions="你是六子棋教练，输出 JSON。",
        input=prompt,
        text={"format": {
            "type": "json_schema", "name": "connect6_move",
            "schema": MOVE_SCHEMA, "strict": True,
        }},
    )
    result = json.loads(response.output_text)
```

完整代码还会检查请求状态、坐标类型、坐标范围、是否为空位、复盘引用手数。模型输出非法或请求失败会回退到代码 AI，页面与数据库记录 `local-fallback`。供应商原始异常不会直接显示在页面。

API Key 只放后端 `.env`；前端只访问本地 Flask。启用外部模型会发送棋盘/棋谱给所配置服务。测试目前使用模拟返回值验证正常、非法与失败路径，未用真实 Key 做在线验证。

实现格式核对来源：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、[Chat Completions 参数](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)。

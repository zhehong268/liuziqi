### 修复 Linux 编译权限

`7213f1a` 已推送，但 GitHub Actions 的两项容器测试失败。日志分别报源码 `Permission denied` 和编译产物 `Operation not permitted`：临时目录默认是 0700，容器里的 nobody 无法读取；生成的二进制又归 nobody 所有，Linux 宿主不能直接改它的权限。Windows 文件共享没有暴露这两个问题。

编译改用权限明确的源码副本和独立输出目录，成功后由宿主复制、设置执行权限并原子保存。容器仍以 nobody 运行。回归测试增加私有目录、源码权限和产物所有权检查。

### 浏览器版与 Windows 客户端

把练习棋规、简单 AI 和规则复盘迁到 JavaScript，通过 IndexedDB 保存棋局。网页继续使用原有水墨界面，上传对战入口在浏览器版替换为客户端下载。GitHub Pages 部署使用相对资源路径，可以直接打开仓库对应的网址。

### 修复安装包资源路径

网站发布和完整容器测试通过。Windows 首次打包失败：spec 文件放在 build 目录后，PyInstaller 把 static 等相对路径也按 build 目录解释。构建脚本改为传入绝对资源路径，保留失败标签，再用修复版本重新构建。

安装程序构建后，自检又报出断言失败。Windows 临时目录可能使用短文件名，而数据目录已转换为绝对长路径，自检改为规范化后比较，并补上每个检查项的错误信息。

### 检查浏览器棋谱文件

实际下载 JSON 后，发现分析完成时棋谱链接没有更新，导出的分析仍为空。原因是下载缓存只比较手数和状态，没有包含分析结果。缓存条件补上分析内容，新增回归测试检查分析前后下载文件和链接复用。

线上验证时，浏览器还在复用旧脚本缓存。生成网站时为脚本、样式链接加入文件内容哈希，内容变化后使用新的资源地址。
